# Hookah Mixer — контекст проекта для AI-агента

Состояние на 2026-10-24. Сайт: https://demansh.github.io/hookah-mixer/ (отладка: `?debug=1`).
Подробная история решений и планы: `~/ai/hookah-mixer/` (актуальны `05-new-scope.md`, `06-next-plan.md`;
`01`–`04c` описывают отменённую «табачную» постановку и устарели).

## Что это
Serverless PWA (GitHub Pages + Jekyll, Vanilla JS ES modules, mobile first, RU/EN). Пользователь вводит
настроение («свежие тропические фрукты с холодком», «Бледный Петербург», «овсянка») и получает 3 микса
из 3–4 **ароматов** с процентами — без брендов, табаков, чаш и крепости. Микс называют кальянщику.
Цвет полоски слева = смелость: зелёная классика с изюминкой, жёлтая эксперимент, красная смелое сочетание.

## Пользователь и правила работы (обязательно)
- Пользователь не разбирается в табаках: **все данные пишет агент**, пользователь только даёт отзывы о вкусе
  и сообщает о странных выдачах. Не просить его размечать данные.
- **Никаких комментариев в коде** (включая docstrings). **Никаких unit-тестов** и Node.js для пользователя.
  Node (≥18, через nvm) агент использует только для своих проверок.
- Тесты/проверки не гонять «в лоб» в основной сессии, если глобальные правила требуют subagent `test-runner`;
  скрипты скилла ниже — это диагностика, их можно запускать.
- Агент **не коммитит и не пушит**: в конце даёт команду `git add -A && git commit -m "..." && git push`.
  В репозитории локально задан `user.email = demansh17@gmail.com` (не рабочий email).
- Пользователь проверяет только на реальном телефоне через задеплоенный GitHub Pages. Не предлагать эмуляторы,
  adb, туннели, Safari-отладку. Локальный Jekyll не нужен.
- UI максимально компактный: без лишних заголовков и поясняющих строк. Ошибок не показываем — вместо них
  эмодзи-мастер и случайные миксы. Любой текст UI — через `_data/i18n/{ru,en}.yml` на обоих языках.
- Безопасность: строгий CSP в `_layouts/default.html`, вывод только через `textContent`.
- Эмодзи — одиночные кодовые точки не новее Emoji 11 (без ZWJ и вариантов пола).
- Планы/исследования сохранять в `~/ai/hookah-mixer/` (≤100 строк, ≤120 символов в строке, разделы:
  запрос пользователя, краткое содержание, основная часть).

## Структура
- `index.html`, `_layouts/default.html` — страница, CSP, мета PWA; `_config.yml` — baseurl `/hookah-mixer`, exclude.
- Раскладка «как мессенджер»: шапка сверху, миксы в середине, внизу закреплённая панель (`form.bottom-bar`: чипы,
  под ними мастер + поле + кнопка). `ui/bottom-bar.js` пишет высоту панели в `--bottom-bar-height` (отступ
  области миксов) и подъём над клавиатурой iOS в `--keyboard-offset` (Visual Viewport API); для Chrome Android —
  `interactive-widget=resizes-content` в meta viewport. Debug-панель сверху; подвала нет.
- Избранное и экраны: `favorites.js` (localStorage `hm.favorites`, версия схемы 1, ключ микса — состав с долями),
  `mix-link.js` (кодирование `?mix=id.share,…&tier=&q=` и строгий разбор), `router.js` (экраны main / `?mix=` /
  `?view=favorites` через History API, сохраняет `debug` и `seed`), `ui/views.js` (страница микса с «Подобрать
  похожие», список избранного), `ui/mix-card.js` (общая карточка), `ui/share.js` (Web Share API, иначе буфер обмена
  + `ui/toast.js`). Пояснение на странице микса пересчитывается `noteForMix`. **Id ароматов не переименовывать** —
  на них ссылаются сохранённое избранное и отправленные ссылки.
- Пустой экран до первого подбора: `#empty-state` — SVG-колба (`flask-conical`, без дыма;
  картинка прячется при высоте < 520px) и подсказка `empty_hint`.
- `assets/js/app.js` — оркестрация: загрузка каталога, состояние (страница, серия повторов), ♡+ (аромат в начало
  запроса → закреплён, обязателен во всех миксах) и ♡̸ (вырезает закреплённое упоминание через `removeSpans` и
  дописывает «, без X»), эмодзи, SW.
- Кнопка подбора — иконка Lucide: ✨ `sparkles` для нового запроса, ↻ `refresh-cw`, если запрос не менялся
  (повторное нажатие = другие варианты); иконка PWA — колба Lucide `flask-conical`
  (`assets/icons/icon.svg`, PNG 512/192/180 рендерятся из него); лицензия в `assets/icons/LICENSE-lucide.txt`.
- `assets/js/engine/` — движок: `text.js` (токены, нечёткое сравнение словоформ), `profile.js` (разбор запроса),
  `graph.js` (пары и матрица категорий), `mixes.js` (пул, перебор, оценка), `shares.js` (доли),
  `recommend.js` (уровни, страницы, разные основы, случайный режим).
- `assets/js/ui/` — `form.js`, `examples.js` (закольцованная лента чипов в обе стороны, ≤240 в DOM: чередуются понятные образы с `chip: true`
  и ароматы), `results.js` (карточки; круглые кнопки Lucide `heart-plus`/`heart-off`
  из `icons.js`; закреплённый аромат помечен сердечком без ♡+; при 3 закреплённых ♡+ скрыта),
  `mood.js` (эмодзи-мастер). `debug.js` — панель `?debug=1` (лог, sha сборки, сброс кэша).
- `data-src/` — исходные данные (правит агент): `tags.csv` (103 аромата + 6 свойств: role, intensity, sweet,
  sour, fresh, синонимы, описания), `category_affinity.csv` (171 пара из 18 категорий), `pairings.csv`
  (1197 пар: affinity −1..1, familiarity classic/known/rare, пояснения RU/EN), `concepts.yaml` (114 образов,
  659 фраз, 48 с `chip: true`; имена собственные с заглавной — сравнение регистронезависимое).
- `assets/data/*.json` — сборка из `data-src/` (руками не править). `tools/validate.py`, `tools/build.py`.
- `sw.js` (Jekyll-шаблон: precache `site.static_files`, версия = sha сборки, network-first) + `manifest.webmanifest`.
- `.claude/skills/fix-query-handling/` — скилл исправления ошибок обработки запросов + диагностические скрипты.
- `notes/` — `review-draft.md` (черновик ревью графа для пользователя, **устарел**: создан до последних
  образов и гастрономии), `feedback.md`, `eval-log.md`, `archive/brands.csv`. `eval/queries.jsonl` — 2 примера.

## Как работает движок (кратко)
1. Разбор: самое длинное совпадение с фразами образов и названиями/синонимами ароматов; словоформы через
   общий префикс + валидное окончание (`WORD_ENDING_PATTERN`); частичное совпадение со словом фразы образа
   (вес ×0.5, слово не из >2 образов); «без X» → исключение; прямо названные ароматы обязательны.
2. Пул: профиль + соседи по графу; если <10 — добор по матрице категорий; свойства тоже дают кандидатов.
3. Перебор всех комбинаций 3–4 ароматов с ограничениями (без конфликтов, ≤1 аромата интенсивности 5,
   ≤2 из категории, хотя бы один ключевой аромат), оценка = релевантность + гармония + свойства − штрафы.
4. Уровни по новизне (доля редких пар + ароматы-«соседи»), разные основы в трёх карточках, повторное нажатие
   «Подобрать» = следующая страница без повторов, по исчерпании — сначала. Пустой/непонятый запрос →
   случайные миксы. Доли: основа 50, роли и потолки по интенсивности, шаг 5%.
5. Рандомизация: зерно на сессию (`?seed=N` воспроизводит, зерно видно в `?debug=1`); к оценке уровня
   добавляется детерминированная добавка ±0.03/±0.035/±0.05 (classic/balanced/bold) — меняется порядок только
   среди близких кандидатов. Без зерна (скрипты `sweep`, `words`, `diagnose` без `--seed`) движок детерминирован.

## Рабочие команды
```bash
uv run tools/validate.py && uv run tools/build.py        # после любой правки data-src/
S=.claude/skills/fix-query-handling/scripts/engine-harness.sh
$S diagnose --pages=3 "запрос"    # разбор, пул, кандидаты, миксы, эмодзи
$S words                          # регрессия словоформ (scripts/wordforms.json) — сейчас 83/83 и 12/12
$S sweep                          # все ароматы/свойства/фразы образов — сейчас 889 запросов, 0 проблем
```
Проверка UI: собрать страницу вручную (подставить Liquid в `_layouts/default.html`), отдать `python3 -m
http.server`, снять скриншот headless Chrome (`--window-size=500,900`; уже 500px не работает).
Service worker проверять только через DevTools Protocol в реальном времени (`uv run --with websocket-client`),
`--dump-dom` с virtual time для SW и IntersectionObserver не годится.

## Известные особенности
- GitHub Pages кэширует файлы 10 минут; service worker (network-first) решает смешивание версий со второго
  открытия после деплоя. Если пользователь видит «старое поведение» — сначала проверить кэш/sha в подвале.
- У узких запросов (один редкий аромат) варианты кончаются к ~5-й перегенерации, затем выдача по кругу (😵).
- Из-за правила разных основ главный аромат образа может отсутствовать в 2-й и 3-й карточке (осознанно).
- Пояснения есть у ~310 из 1197 пар. Новизна (classic/known/rare) — оценка агента, уточнять по отзывам.
