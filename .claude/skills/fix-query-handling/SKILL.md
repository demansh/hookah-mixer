# Исправление ошибок обработки запросов

Пользователь присылает запрос и что пошло не так. Задача — найти класс ошибки, исправить его
**для всего класса запросов**, а не для одного слова, и доказать, что ничего не сломалось.

## Правила проекта (не нарушать)
- Без unit-тестов и без Node.js у пользователя: Node (≥18, есть через nvm) — только для моих проверок ниже.
- Никаких комментариев в коде. Тексты интерфейса — только через `_data/i18n/{ru,en}.yml`, на обоих языках.
- Вывод в DOM только через `textContent`. Эмодзи — одиночные, не новее Emoji 11.
- Данные (`data-src/`) пишу я; пользователь даёт отзывы о вкусе. Не просить его размечать данные.
- Не коммитить и не пушить: в конце дать пользователю команду `git add -A && git commit -m "..." && git push`.

## Как устроен разбор (где искать причину)
```
запрос → text.js tokenize/tokenMatchScore → profile.js parseQuery → mixes.js buildPool/generateCandidates
       → recommend.js уровни, страницы, случайный запасной режим → shares.js доли → ui/mood.js эмодзи
```
- `engine/text.js` — нечёткое сравнение слов: общий префикс + **хвост обязан быть окончанием**
  (`WORD_ENDING_PATTERN`), отступ окончания назад (`ENDING_BACKOFF`), короткие слова на -й/-ь теряют букву.
- `engine/profile.js` — фразы образов и названия/синонимы ароматов, побеждает самое длинное совпадение;
  частичное совпадение со словом из фразы образа (вес ×0.5, слово не должно встречаться больше чем
  в 2 образах); «без X» → исключение; прямо названные ароматы → `required`; противоречия.
- `engine/mixes.js` — пул: профиль + соседи по явным парам (≥0.5); если пул < 10 — добирается по
  матрице категорий; ароматы от свойств тоже бывают «семенами»; холодок приводит соседей, только если он один.
- `engine/recommend.js` — 3 уровня (classic/balanced/bold), разные основы в карточках, страницы без
  повторов, уровень не пропадает (подходящие кандидаты + остальные), пустой результат → случайный режим.
- `ui/mood.js` — приоритеты: пусто 🧙 → по кругу 😵 → серия повторов 😅😰🥵 → противоречие 🤨 →
  исключения 🧐 → не понял/случайный режим 😕 → образ 🤩 → аромат 😊 → только частично 🤔.
- Данные: `data-src/tags.csv` (ароматы, свойства, синонимы), `concepts.yaml` (образы),
  `pairings.csv`, `category_affinity.csv`. После правок: `uv run tools/validate.py && uv run tools/build.py`.

## Шаг 1. Воспроизвести
```bash
S=.claude/skills/fix-query-handling/scripts/engine-harness.sh
$S diagnose --pages=3 "запрос пользователя"
```
Показывает: что совпало (`~partial`, `-` для исключений), веса, свойства, обязательные, пул и число
кандидатов, миксы по страницам и эмодзи. Скрипт копирует `assets/` во временную папку, поэтому сначала
`uv run tools/build.py`, если правились данные.

## Шаг 2. Определить класс (разобранные случаи)
| Симптом | Пример | Причина | Исправление |
|---|---|---|---|
| 😕 на обобщающее слово | «алкоголь», «орехи» | нет образа категории | образ `category-*` в `concepts.yaml`, ароматы категории с равными весами |
| 😕 на аромат | «чили» | нет синонима | синоним в `tags.csv` (не словоформу!) |
| 😕 на устойчивую фразу | «бабушкино варенье» | нет образа | новый образ; 2–5 формулировок RU, 1–3 EN |
| 😕 на фразу из общих слов | «вечер у бабушки» | частичное совпадение отбрасывает слова из >2 образов | это норма; при частых жалобах — конкретный образ |
| ложное совпадение | «колбаса» → кола, «роман» → ром | хвост слова не окончание | `WORD_ENDING_PATTERN`; **не ослаблять** проверку |
| словоформа не распознана | «тропическими», «чаем» | префикс съел гласную / стем на -й | `ENDING_BACKOFF`, `SOFT_FINAL_LETTERS`, осторожно расширить окончания |
| не то слово выиграло | «сливочное» → слива | оценка в пользу коротких слов | нормировка на длину более длинного слова (уже есть) |
| частичное совпадение раздувает профиль | «летний вечер на террасе» | слово из многих образов | `PARTIAL_MAX_CONCEPTS_PER_TOKEN`; добавить точный образ |
| 😊 но миксов нет / случайные | «энергетик» | узкий пул, расхождение `canFillMix` и долей | `MIN_POOL_SIZE`, `mixLimits` с `requiredIds`; запасной режим — последняя страховка |
| только свойство | «пряности», «горчинка» | нет семян для соседей | `expansionSeeds` из ароматов свойства; образ категории |
| одна основа во всех карточках | «тропики» → везде манго | разные веса в образе | правило разных основ; в обобщающих образах равные веса |
| уровень пропал на перегенерации | «гранат» | фильтр уровня исчерпан | в уровне сначала подходящие, затем остальные; лимит соседей классики только при ≥2 семенах |
| не та эмодзи | — | смотреть приоритеты `resolveMood` и поля профиля | править `mood.js`, не движок |
| на телефоне старое поведение | эмодзи не меняется | кэш/service worker | не баг: сверить sha в подвале, `?debug=1` → сброс кэша |

**Данные или движок?** Одно отсутствующее слово/образ — правка данных. Целый класс запросов
(словоформы, пустые выдачи, узкие пулы, уровни) — правка движка. Сомневаешься — сначала данные.

## Шаг 3. Исправить
- Данные: правка `data-src/*`, затем `uv run tools/validate.py` (0 errors) и `uv run tools/build.py`.
  Валидатор ловит дубли терминов между ароматами и абстрактные eval-запросы, совпадающие с фразами образов.
- Движок: константы вынесены в начало файлов; менять их точечно и проверять эффект через `diagnose`.

## Шаг 4. Доказать (обязательно после любой правки движка или данных)
```bash
$S words      # регрессия словоформ и посторонних слов (scripts/wordforms.json), exit 1 при промахе
$S sweep      # все ароматы, свойства и фразы образов RU+EN: 3 микса, доли = 100, без запасного режима
$S diagnose --pages=3 "исходный запрос"
```
- Новый случай всегда добавлять в `scripts/wordforms.json`: в `shouldMatch` (запрос → id аромата или
  образа) или в `shouldNotMatch` (посторонние слова). Так ошибка больше не вернётся незамеченной.
- Для изменений интерфейса — скриншот в headless Chrome (`--window-size=500,900`, ширина <500 не работает).

## Шаг 5. Отчитаться
Кратко: причина (класс ошибки), что изменено, цифры проверки (`words`, `sweep`), результат на исходном
запросе. В конце — команда коммита для пользователя.
